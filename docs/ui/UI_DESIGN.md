# 网店账本 UI 实现规范

状态：首版 UI 方向与原型，等待视觉复核；不是已实现的 Flutter 应用。

## 设计来源

- 工作台：用户本机 Open Design 0.24.1。
- 项目：`PersonalFinancesPro · UI规划`，ID `4e9536c2-a3f8-4c3f-acd9-11eae8f64a62`。
- OpenDesign 内置 `frontend-design` skill 与 `material` 设计系统。
- Material 包的 DESIGN.md 使用紫色，而实际 tokens.css 使用蓝色；本项目统一采用 tokens.css 的蓝色体系，不混用两套主色。
- 原型由当前会话在 OpenDesign 工作台内创作和发布，没有启动外部设计代理。正式实现使用 Flutter Material 3 原生组件，不嵌入此网页。

## 视觉方向

“紧凑经营工具”：蓝白、低装饰、金额优先。保留清楚的店铺归属和业务来源，避免把经营现金流包装成利润。

- 色彩语义：收入绿色、支出红色；同时使用正负号和文字，不只靠颜色传达方向。
- 字体：平台中文系统字体；金额使用等宽数字。字号 12/14/16/20/24/32，普通正文至少 14。
- 间距：4/8/12/16/24/32；页面内边距 16，卡片内边距 16，卡片间距 12。
- 圆角：卡片 12、输入框 8，选择标签采用胶囊形。无玻璃、复杂渐变或大面积阴影。
- 点击目标至少 48×48 logical pixels；金额输入和保存按钮不能被键盘遮挡。
- 普通状态切换 150ms；尊重系统减少动态效果设置。
- Flutter 主题使用相应 ColorScheme 语义角色，不将全部页面颜色散落在 Widget 中。

## 页面结构与组件映射

### 1. 首页

1. 顶部：网店账本标题、当前店铺选择器。
2. 期间说明：示例日期/月度范围；正式版可选期间。
3. 首要信息：平台外现金净额；辅助收入、支出。明确“不是店铺利润”。
4. 待办：厂家待付款金额，可进入采购列表。
5. 快捷入口：采购付款、问题件收入、快递充值。
6. 最近现金账：名称、分类、店铺、日期、正负金额。
7. 底部固定四入口：首页、账本、AI记账、设置。

Flutter：AppBar、DropdownButtonFormField/菜单、Card、ListTile、FilledButton、NavigationBar。金额汇总不使用自定义画布图表。

### 2. 账本

- 三个业务视图：现金账 / 采购单 / 快递预付。
- 现金账可按店铺与方向筛选；日分组账单显示店铺和分类，不把采购额混入现金支出。
- 采购单同时显示应付、已付、待付三个口径；付款按钮进入明确的付款表单。
- 快递预付分开显示充值、消耗、记录余额，并标明不是服务商实时余额。
- 点击现金账进入详情；原型演示详情只读，正式版提供编辑、作废及变更记录。
- 主操作为“记一笔”，从收入/支出及常用业务类型进入相应表单。

Flutter：SegmentedButton、FilterChip、ListView、ListTile、FloatingActionButton.extended；采购和快递复用原生 Card。

### 3. 手动记账

- 普通收支：方向、金额、店铺、分类、账户、交易对象、日期、备注。
- 采购：商品明细、厂家、归属店铺、厂家运费；付款金额与付款账户分开，不默认全额已付。
- 二次销售：原店铺、数量、实收金额、渠道、买家、收款账户；运费/手续费另有付款账户。
- 快递充值：预付账户、充值金额、付款账户；消耗使用独立入口，不再记现金支出。
- 只在字段有效、关联完整时启用保存；保存中禁用二次提交。
- 取消脏表单先确认；失败保留输入，错误贴近字段，不能只弹一条泛化 Toast。
- 原型的手动表单仅演示普通收支并只写内存，不冒充完整采购或充值业务实现。

Flutter：独立滚动页面中的 Form/TextFormField、DropdownButtonFormField、日期选择器、底部安全区 FilledButton；不是把复杂表单塞进固定高度弹窗。

### 4. AI 记账

1. 隐私与服务商说明，无 Key 时显示去设置入口。
2. 中文输入框与常用示例句；发送时可取消。
3. 缺失字段问题、候选店铺/账户。
4. 结构化草稿卡片：逐笔明确收入/支出、金额、归属、账户及关联业务。
5. 确认前可编辑；确认后显示成功与去账本入口，同一草稿不能再次入账。
6. 错误时保留原句，并提供手动录入入口。

原型只展示预置示例：“一店12件问题衣服卖给老王，微信收到360元，支付宝付20元运费”。不识别任意句子、不调用模型。

Flutter：TextField、消息列表、Card、ProgressIndicator、FilledButton；草稿与真实账单使用不同状态类型。

### 5. 设置

- 店铺、账户、厂家、分类及渠道管理。
- AI：开关、服务商、HTTPS Base URL、模型、密码样式 Key 字段、连接测试、清除。
- 改地址时显示凭据接收主机及确认；Key 不默认明文展示，也不随备份导出。
- 备份、恢复、CSV 导出；恢复显示替换风险并要求先备份。
- 数据范围与隐私说明、MIT 和源码链接。

原型禁用 Key 输入、连接测试及真实文件操作，明确提示“仅正式 App 可用”，没有虚假成功提示。

## 状态规范

| 状态 | 可见内容和行为 |
|---|---|
| 初次空账本 | 解释平台外范围，主操作为创建店铺/记第一笔；无虚假统计 |
| 读取中 | 固定区域进度提示，避免整页布局大幅跳动 |
| 本地读取失败 | 错误说明和重试；不展示旧数据为新数据，不清库 |
| 无匹配账单 | 保留筛选，提示取消筛选；与初次空账本区分 |
| 记账编辑 | 字段校验、脏表单提醒、金额精度提示 |
| 保存中 | 阻止重复点击，等待事务结果 |
| AI 未配置 | 手动记账可用，说明配置入口 |
| AI 失败 | 保留原句，明确鉴权/网络/限流/格式错误，提供手动入口 |
| AI 已确认 | 确认按钮禁用，显示草稿已保存；再次触发不生成重复记录 |
| 作废记录 | 详情明确状态；汇总不计入，恢复前检验关联约束 |

原型提供正常/空/加载/错误的预览切换器，属于设计评审控件，不能进入正式 App 的生产 UI。

## 响应式与无障碍

- 以 390 logical pixels 作为移动布局参考，不写死页面宽度。
- 验证 320、390 和 430 宽度无水平溢出；文字缩放后允许卡片增高。
- 大屏可限制内容宽度，不把手机字段无限横向拉伸；正式版后续按实际平板需求决定 NavigationRail。
- 系统状态栏和导航栏由 Flutter 系统安全区处理，不在应用内绘制假的时间、电量或刘海。
- 语义按钮、清楚的字段标签、键盘焦点和返回路径。弹层返回可取消，不吞掉系统返回手势。
- 示例数据始终可见标记；原型不包含真实经营信息。
